> این فایل در git است، پس هیچ ریست فکتوری‌ای نمی‌تواند از بینش ببرد.

---

## ۰. جواب کوتاه سوال «لینوکس یا ویندوز؟»

**هر دو، همزمان.** معماری Buzz خودش این را جواب می‌دهد: یک **رله**، چند **کلاینت**.

```
        رله (relay)  ← تنها جایی که داده واقعاً می‌ماند
        ws://localhost:3000
        Postgres + Redis + MinIO
              ▲           ▲            ▲
              │           │            │
      دسکتاپ لینوکس  دسکتاپ ویندوز   موبایل
              │
        ایجنت‌ها روی همین دستگاه اجرا می‌شوند
        (Claude Code / Codex / Goose از طریق buzz-acp)
```

رله را **یک بار** بالا می‌آوری. بعد از آن، کلاینت ویندوز و کلاینت لینوکس هر دو با
**یک کلید هویت** به همان community وصل می‌شوند و همان کانال‌ها، پیام‌ها، تنظیمات
ایجنت‌ها و حافظه‌شان را می‌بینند.

---

## ۱. پشتیبان — این را اول انجام بده

درس گران‌قیمتِ دفعهٔ قبل: چیزی که فقط روی دیسک بود، با ریست رفت.

| چیز | کجاست | جبران‌پذیر؟ |
|---|---|---|
| **کلید خصوصی (nsec)** | کلاینت دسکتاپ، بار اول ساخته می‌شود | ❌ **هرگز**. گمش کنی، حساب رفته |
| `RELAY_OWNER_PUBKEY` | متغیر محیطی رله | با کلید بالا دوباره ساخته می‌شود |
| URL رله | یک رشتهٔ متن | یادداشتش کن |
| محتوای community | Postgres روی رله | فقط با بکاپ Postgres |
| `.env` رله | کنار مخزن | حاوی رمزهاست، در git نگذار |

**همین حالا:** کلید خصوصی را در یک password manager بگذار. Buzz صریح می‌گوید اگر
آن را گم کنی هیچ راهی برای ورود دوباره نیست. مالکیت رله هم به همان کلید بند است،
پس بدون آن حتی روی رلهٔ سالم هم دیگر ادمین نیستی.

## ۲. ساده‌ترین مسیر (توصیهٔ من)

اگر فقط می‌خواهی کار کند، نه اینکه از سورس بسازی:

1. **کلاینت را نصب کن** — از [releases](https://github.com/block/buzz/releases/latest):
   - ویندوز: `Buzz_<version>_x64-setup_alpha-unsigned.exe`
   - لینوکس: `Buzz_<version>_amd64.AppImage` یا `.deb`

   نسخهٔ ویندوز code-sign نشده، پس SmartScreen هشدار می‌دهد:
   **More info → Run anyway**.

2. **روی ویندوز، Git for Windows را نصب کن** — [git-scm.com/download/win](https://git-scm.com/download/win)

   دلیلش مهم است: ابزار shell ایجنت‌ها دستورها را زیر bash اجرا می‌کند. لینوکس و مک
   خودشان bash دارند؛ ویندوز ندارد. Git for Windows همراهش Git Bash می‌آورد و Buzz
   در زمان اجرا همان را پیدا می‌کند. اگر bash دیگری می‌خواهی، `BUZZ_SHELL` را به
   مسیرش بگذار.

3. **یک رله لازم داری.** سه گزینه:
   - **محلی روی همین لپ‌تاپ** (بخش ۳) — رایگان، بدون سرور
   - **Railway** — استقرار تک‌کلیکی، بدون مدیریت سرور
   - **VPS خودت** — بستهٔ `deploy/compose/` در مخزن

4. کلاینت پیش‌فرض به `ws://localhost:3000` وصل می‌شود. برای رلهٔ دیگر، قبل از اجرا
   `BUZZ_RELAY_URL` را ست کن، یا از داخل خود برنامه رله را عوض کن.

## ۳. رلهٔ محلی روی لپ‌تاپ (از سورس)

### پیش‌نیازها

Docker، به‌علاوهٔ [Hermit](https://cashapp.github.io/hermit/) **یا** دستیِ:
Rust ‏1.88+ (مخزن روی 1.95.0 پین است)، Node ‏24+، pnpm ‏10+، `just`.

> Hermit روی لینوکس و مک است. **روی ویندوز مسیر دستی را برو** و دستورها را در
> **Git Bash** اجرا کن، نه PowerShell — چون recipeهای Justfile با
> `#!/usr/bin/env bash` نوشته شده‌اند.

### یک‌بار

```bash
git clone https://github.com/block/buzz.git && cd buzz
. ./bin/activate-hermit     # فقط لینوکس/مک؛ روی ویندوز رد کن
just setup && just build
```

`just setup` این کارها را می‌کند: `.env.example` را به `.env` کپی می‌کند،
ابزارها را می‌آورد، سرویس‌های Docker را بالا می‌آورد، migration می‌زند، و
کلید رلهٔ محلی را می‌سازد.

### هر روز

```bash
. ./bin/activate-hermit     # فقط لینوکس/مک
just dev                    # رله + دسکتاپ با هم
```

یا در دو ترمینال جدا، وقتی لاگ رله را جدا می‌خواهی:

```bash
just relay          # ترمینال ۱
just desktop-dev    # ترمینال ۲
```

### پورت‌هایی که اشغال می‌شوند

| پورت | چه چیزی |
|---|---|
| ۳۰۰۰ | رله (WebSocket + REST) |
| ۸۰۸۰ | health |
| ۹۱۰۲ | metrics |
| ۵۴۳۲ | Postgres |
| ۶۳۷۹ | Redis |
| ۹۰۰۰ | MinIO (رسانه، پروتکل Blossom) |

`just dev` اگر ۳۰۰۰ یا ۸۰۸۰ یا ۹۱۰۲ اشغال باشد **عمداً بالا نمی‌آید** تا اشتباهی
به یک رلهٔ کهنه وصل نشوی. معمولاً یک `buzz-relay` جامانده است؛ ببندش و دوباره بزن.

## ۴. هر دو سیستم‌عامل روی یک community

اینجا جواب اصلی سوالت است.

**اگر رله روی لپ‌تاپ لینوکسی خودت است** و می‌خواهی از ویندوز هم وصل شوی:

1. IP لینوکس را در شبکهٔ محلی پیدا کن (`ip addr` یا `hostname -I`)
2. `.env` رله از قبل `BUZZ_BIND_ADDR=0.0.0.0:3000` دارد، یعنی روی کل شبکه گوش می‌دهد
3. روی ویندوز، کلاینت را با این مقدار اجرا کن:
   ```
   BUZZ_RELAY_URL=ws://<آی‌پیِ-لینوکس>:3000
   ```
4. **با همان کلید خصوصی وارد شو** — نه کلید جدید. کلید جدید یعنی هویت جدید.

**اگر رله روی VPS است**، هر دو سیستم‌عامل فقط URL همان رله را می‌گیرند و تمام.
هیچ چیز دیگری لازم نیست جابه‌جا شود.

## ۵. فعال‌کردن ۴ AI در صفحهٔ «Set up your agent harnesses»

این سخت‌ترین قسمت است و دلیلش یک چیز ساده است که هیچ‌جا داد نمی‌زند:

> **هر harness به دو باینری نیاز دارد، نه یکی: خود CLI، و یک آداپتور ACP جدا.**

صفحهٔ setup برای هر کدام یکی از این حالت‌ها را نشان می‌دهد. معنی دقیقشان:

| برچسب روی کارت | یعنی | کاری که باید بکنی |
|---|---|---|
| `READY` | هم CLI هست هم آداپتور | هیچی |
| `CLI detected; ACP adapter missing` | CLI هست، آداپتور نیست | آداپتور را با npm نصب کن |
| `CLI not detected` | خود CLI نصب نیست | اول CLI، بعد آداپتور |
| `adapter outdated` | آداپتور از بستهٔ منسوخ (زیر ۱٫۰) | حذف و نصب دوباره (پایین) |

### مهم: آداپتورها را با ترمینال نصب نکن

Buzz **نودِ خودش را دارد** و نصب آداپتور را خودش انجام می‌دهد. دکمهٔ `Install`
روی همان کارت را بزن؛ نه npm خودت را.

| چیز | مسیر روی لینوکس |
|---|---|
| نود مدیریت‌شدهٔ Buzz (پین‌شده روی **v24.18.0**) | `~/.local/share/Buzz/runtimes/node/v24.18.0/linux-x64/bin/` |
| محل نصب آداپتورها | `~/.local/share/Buzz/node-tools/` |

چرا مهم است: اگر نودِ سیستم تو قدیمی باشد (مثلاً ۱۸ که EOL شده)، `npm install -g`
دستی یا خطا می‌دهد یا آداپتوری نصب می‌کند که بالا نمی‌آید. نودِ مدیریت‌شدهٔ Buzz
این را کامل دور می‌زند و به `sudo` هم نیاز ندارد.

دستورهای npm پایین فقط برای وقتی است که می‌خواهی دستی کار کنی **و نودت ۲۴ به بالاست**.

### دستورهای دقیق

**Goose** — تنها موردی که آداپتور جدا نمی‌خواهد؛ خودِ `goose` آداپتور ACP است.

```bash
# لینوکس / مک
curl -fsSL https://github.com/aaif-goose/goose/releases/download/stable/download_cli.sh | CONFIGURE=false bash
```
```powershell
# ویندوز
$env:CONFIGURE='false'; irm https://raw.githubusercontent.com/aaif-goose/goose/main/download_cli.ps1 | iex
```

**Claude Code** — دو مرحله.

```bash
# ۱) CLI  (لینوکس/مک)
curl -fsSL https://claude.ai/install.sh | bash
# ویندوز:  irm https://claude.ai/install.ps1 | iex

# ۲) آداپتور ACP
npm install -g @agentclientprotocol/claude-agent-acp
```

**Codex** — دو مرحله.

```bash
# ۱) CLI  (لینوکس/مک)
curl -fsSL https://chatgpt.com/codex/install.sh | sh
# ویندوز:  irm https://chatgpt.com/codex/install.ps1 | iex

# ۲) آداپتور ACP
npm install -g @agentclientprotocol/codex-acp
```

**Buzz Agent** — داخلی است. نه CLI می‌خواهد نه آداپتور. همیشه `READY`.

### Goose بعد از نصب هنوز کار نمی‌کند — provider می‌خواهد

دستور نصب رسمی `CONFIGURE=false` دارد، یعنی **عمداً بدون تنظیمات** نصب می‌شود.
`goose --version` جواب می‌دهد ولی Buzz ایجنت را آماده نمی‌داند، چون preset اش
`required_normalized_fields: ["model", "provider"]` است.

```bash
goose configure
```

یا از داخل Buzz: `Settings → Agents` → ایجنت Goose → provider و model را همان‌جا
بگذار. Buzz آنها را با `GOOSE_PROVIDER` و `GOOSE_MODEL` پاس می‌دهد.

**انتظارِ درست دربارهٔ کلید:** لاگین اشتراکی Claude یا ChatGPT که برای Claude Code
و Codex انجام دادی، به Goose منتقل نمی‌شود. مگر اینکه در لیست providerها گزینه‌ای
باشد که از همان CLI احراز‌هویت‌شده استفاده کند، وگرنه برای provider انتخابی‌ات یک
API key جدا لازم داری که جداگانه هزینه دارد.

### آداپتورها را در PATH سیستم نگرد

```bash
which codex-acp claude-agent-acp      # هیچی برنمی‌گرداند — طبیعی است
ls ~/.local/share/Buzz/node-tools/bin/  # claude-agent-acp  codex-acp
```

Buzz آداپتورها را در پوشهٔ خودش نصب می‌کند و از همان‌جا صدایشان می‌زند. خالی بودن
`which` نشانهٔ خرابی نیست.

### تلهٔ آداپتور منسوخ

بسته‌های `@zed-industries/*` نسل قبلی‌اند و Buzz ردشان می‌کند. اگر کارت
`outdated` نشان داد، دو مرحله لازم است، نه یکی:

```bash
npm uninstall -g @zed-industries/codex-acp
npm install  -g @agentclientprotocol/codex-acp
```

همین برای Claude Code: `@zed-industries/claude-code-acp` جای خود را به
`@agentclientprotocol/claude-agent-acp` داده است.

> نصب آداپتورها با npm است، پس **Node باید روی همان دستگاه نصب باشد** — حتی اگر
> رله را جای دیگری اجرا می‌کنی. آداپتورها روی دستگاه تو اجرا می‌شوند.

### لاگین — نصب کافی نیست

`READY` بودن یعنی باینری‌ها پیدا شدند، نه اینکه احراز هویت شده‌ای. خودت چک کن:

```bash
claude auth status     # باید بدون خطا جواب بدهد
codex login status     # خروج با کد ۰ یعنی لاگین هستی
```

اگر نبودی: `codex login` را بزن، و برای Claude خود `claude` را اجرا کن تا
احراز هویت را کامل کند.

نمونهٔ واقعی از یک دستگاه که کارت Claude Code رویش `READY` بود:

```json
{ "loggedIn": false, "authMethod": "none", "apiProvider": "firstParty" }
```

`READY` بود و لاگین نبود. دقیقاً همان چیزی که بالا گفته شد.

### خطای «Missing optional dependency» در Codex

```
Error: Missing optional dependency @openai/codex-linux-x64.
Reinstall Codex: npm install -g @openai/codex@latest
```

این یعنی Codex از طریق npm نصب شده و باینری مخصوص پلتفرم نیامده — باگ شناخته‌شدهٔ
`optionalDependencies` در npm، که روی نودهای قدیمی بیشتر پیش می‌آید.

نصب دوبارهٔ npm معمولاً همان جا دوباره گیر می‌کند. **راه مطمئن‌تر: نصب‌کنندهٔ رسمی
که باینری بومی می‌آورد و اصلاً به نود کاری ندارد:**

```bash
npm uninstall -g @openai/codex
curl -fsSL https://chatgpt.com/codex/install.sh | sh
# ترمینال را ببند و باز کن
codex --version
```

همین مسیر است که در `discovery.rs` خود Buzz به‌عنوان دستور نصب Codex ثبت شده.

### فایل‌های تنظیمات (اینها را در پشتیبان بگذار)

| harness | مسیر |
|---|---|
| Goose | `~/.config/goose/config.yaml` |
| Claude Code | `~/.claude/settings.json` |
| Codex | `~/.codex/config.toml` |

### چند نکتهٔ عملی

- روی ویندوز، آن `curl ... | bash`ها را در **Git Bash** بزن، نه PowerShell —
  یا از نسخهٔ PowerShell که بالا نوشتم استفاده کن.
- «More harnesses (Cursor, Grok, Amp…)» بعد از setup از **Settings → Agents**
  اضافه می‌شوند. لازم نیست همان اول همه را داشته باشی.
- می‌شود **Skip for now** زد و بعداً برگشت. برای شروع یکی کافی است.
- **تنظیمات ایجنت‌ها روی رله می‌ماند، نه روی دستگاه.** پس وقتی از لینوکس به ویندوز
  می‌روی، ایجنت‌ها با همان نام و حافظه سر جایشان هستند؛ فقط CLIها و آداپتورها را
  باید روی سیستم‌عامل جدید نصب کنی.

دو چیز که جلوی سوختن توکن را می‌گیرد:

- تعداد دورِ بحث بین ایجنت‌ها را صریح بگو («هر کدام سه نوبت»)
- حق فراخوانی را محدود کن. اگر فقط lead بتواند بقیه را صدا بزند، حلقهٔ بی‌پایانِ
  جواب‌به‌جواب شکل نمی‌گیرد

برای اسکریپت و ابزار، `BUZZ_PRIVATE_KEY` را ست کن و از `buzz-cli` استفاده کن —
ورودی JSON، خروجی JSON، ساخته‌شده برای فراخوانی از سمت مدل.
