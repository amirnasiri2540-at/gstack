# تیم هوش مصنوعی شما — ساختار ماژولار v3 — راهنمای راه‌اندازی و استفاده

«یک بار توضیح بده؛ همه هوش‌های مصنوعی هماهنگ روی پروژه کار کنند.»

معماری این نسخه را **خود Founder (شما)** طراحی کرده است: ۵ ماژول + ۲ همکار، با
قوانین ضدتداخل. ابتکارهای پیشکسوت‌ها هم حفظ شده: نقد ناشناس (llm-council کارپاتی)،
دفتر تصمیم فقط-افزودنی (gstack گری تن)، آیین تحویل شیفت (تیم‌های مهندسی واقعی).

## ساختار تیم

| عضو | نقش |
|-----|-----|
| **Founder (شما)** | تعیین هدف، تصمیم نهایی، نگهبان حافظه |
| **Claude** | میزبان ۵ ماژول: A تحلیل ← B طراحی ← C تحقیق ← D پیاده‌سازی ← E تست (هر کدام یک چت تازه) |
| **ChatGPT** | هماهنگ‌کننده منطقی: جمع‌بندی، حل تضاد، فیلتر هماهنگی |
| **Gemini** | لایه تحقیق خارجی: جستجوی بیرونی، مقایسه منابع (خوراک ماژول C) |

**قانون طلایی:** تفکیک کامل وظایف ← جریان خطی ← عدم تداخل ← مناظره کنترل‌شده ← تصمیم Founder ← اجرا

## راه‌اندازی (یک‌بار، ~۱۵ دقیقه)

1. **خانه حافظه:** پوشه‌ای در Google Drive بسازید و چهار فایل PROJECT، DECISIONS،
   STATUS و MODULES را داخلش بگذارید. PROJECT.md را با پروژه واقعی‌تان پر کنید.
2. **Claude:** فایل `ai-council-skill.zip` را در Settings ← Capabilities ← Skills آپلود کنید.
3. **ChatGPT:** یک Custom GPT بسازید و کل متن `COUNCIL-PROTOCOL.md` را در Instructions بگذارید.
4. **Gemini:** یک Gem بسازید و همان متن را در Instructions بگذارید.

## اجرای یک چرخه کامل (گام‌به‌گام)

```
شما: صورت‌مسئله را می‌نویسید
 ۱. چت تازه Claude ← کارت ماژول A + فایل‌های حافظه + صورت‌مسئله ← خروجی A
 ۲. چت تازه Claude ← کارت B + حافظه + خروجی A                    ← خروجی B
 ۳. Gemini ← «نیازهای تحقیق» از خروجی B                          ← یافته‌های بیرونی
 ۴. چت تازه Claude ← کارت C + حافظه + خروجی B + یافته‌های Gemini ← خروجی C
 ۵. چت تازه Claude ← کارت D + حافظه + خروجی B و C               ← نسخه اولیه
 ۶. چت تازه Claude ← کارت E + حافظه + خروجی D                    ← گزارش تست
 ۷. ChatGPT ← همه خروجی‌ها                                       ← جمع‌بندی + تضادها
 ۸. Debate: جمع‌بندی را بی‌نام (عضو الف/ب/ج) به Claude و Gemini بدهید تا نقد کنند
 ۹. اصلاح نهایی ← تصمیم شما (ثبت به‌صورت D-XXX در DECISIONS.md)
۱۰. اجرا — و در پایان: «به‌روزرسانی حافظه بده» و بلوکش را در فایل‌ها کپی کنید
```

**حلقه بازخورد:** اگر ماژول E گفت «برگشت به ماژول X»، همان ماژول را با گزارش E دوباره
اجرا کنید و زنجیره را از همان‌جا ادامه دهید. **حداکثر ۲ دور** — بعدش توقف و تصمیم با شماست.

**نکته صرفه‌جویی:** برای مسئله‌های کوچک لازم نیست همه ۵ ماژول را اجرا کنید — مثلاً یک
سؤال تحقیقی فقط C لازم دارد، یک باگ کوچک فقط D و E. چرخه کامل مال کارهای بزرگ است.

## چرا این سیستم ضد-جاماندگی است

مغز پروژه در فایل‌های متنی Drive شماست، نه در هیچ AI ای. هر عضوی از دسترس خارج شد
(فیلتر، قطعی، اتمام اشتراک)، جایگزینش — هر AI دیگری — با خواندن همان فایل‌ها از
همان‌جا ادامه می‌دهد. ماژول‌ها هم چون در جلسه‌های جدا اجرا می‌شوند، خراب‌شدن یک جلسه
فقط همان یک ماژول را می‌اندازد، نه کل زنجیره را.

## قدم بعدی (وقتی چرخه جا افتاد)

مرحله بعد، خودکارسازی همین زنجیره با n8n + LiteLLM است تا کپی‌پیست بین ماژول‌ها هم حذف
شود. چند چرخه دستی که رفتید، گلوگاه‌ها را حس می‌کنید — آن موقع دقیقاً می‌دانید چه چیزی
را خودکار کنیم.
