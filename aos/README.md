# AOS (Maestro)

One idea, six roles, one shipped artifact. No agent framework.

```bash
cd aos && npm install
npm run setup                                     # resolve real model slugs
npm run aos -- "build a single-page tip calculator"
```

Both `npm run aos` and `npm run setup` also work from the repository root.

Every run writes to `runs/<id>/`:

| File | What it is |
|---|---|
| `artifacts/` | what was actually built, sandboxed |
| `FOUNDER_BRIEF.md` | one page, written on every exit including failures |
| `cost.json` | per-role and per-model spend, derived from the event log |
| `events.jsonl` | append-only trace of every request and response |
| `workorder.json` | final state of the object the roles passed between them |

## No key yet, or no egress

```bash
npm run setup -- --offline
npm run aos -- "your idea"
```

Offline stubs exercise the state machine, the sandbox, the budget meter and the
delivery gate without calling a model. Nothing they produce is model output, and
the artifact, the cost report and the brief all say so. It proves the machine
works; it proves nothing about quality.

If your machine can reach the router but this one cannot, fetch the model list
elsewhere and hand it over:

```bash
curl https://openrouter.ai/api/v1/models > models.json
npm run setup -- --from-file models.json
```

## The roles

| Role | Owns | Refuses to |
|---|---|---|
| MUSE | three divergent options, each with its own "why not" | pick a winner |
| ATLAS | decompose, assign, set tier, hold the WorkOrder | write code |
| FORGE | runnable artifacts | produce prose deliverables |
| ECHO | independent critique from a different provider | praise |
| SENTINEL | reproducible defects with evidence | file without repro steps |
| HERALD | package, brief, run the delivery gate | accept a doc-only handoff |

Roles are data. A seventh role is a seventh file in `roles/` plus an entry in
`config/routing.yaml`. There is no code change, and a test proves it.

## Configuration

`config/routing.yaml` is the hypothesis: a provider preference order and a price
tier per role. It contains no model slugs.

`config/routing.lock.yaml` is generated by `npm run setup` from the router's
live model list. Never hand-edit it. A model id typed from memory fails as a 404
three roles into a paid run, which is the whole reason slugs live in a generated
file.

Point at a different router with `AOS_ROUTER_BASE_URL`; anything speaking
OpenAI-compatible `/chat/completions` works. The key is `AOS_ROUTER_API_KEY` (or
`OPENROUTER_API_KEY`) in `.env`.

## What holds the thing together

- **One call site.** `callModel()` in `src/core/router.ts`. A static test fails
  if a second one appears.
- **Budget halts before spending, not after.** The pre-flight estimate runs
  before the request goes out and deliberately over-estimates.
- **One repair, then a different model, then stop.** Three attempts, fixed.
  "Retries until it works" is how a $1 run becomes a $40 run.
- **Model output is untrusted input.** Artifact paths go through a sandbox that
  refuses traversal, absolutes, dotfiles and symlinked parents.
- **The pipeline is an async generator.** The CLI is a render function over it.
  A bot or web adapter is another render function, not another pipeline.
- **Every exit writes the brief.** Budget halts and gate refusals included.
